# A股正式执行回测与逐日账本 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将阶段五冻结的 `size_stratified_buffered` 目标权重，在2005–2016研究期内转化为包含A股交易约束、历史费用、未成交订单和逐日对账的正式回测结果，为打开验证期前的模型冻结提供可信证据。

**Architecture:** 阶段六不扩展阶段三MVP回测器，而是新增独立的执行数据层、订单状态机、费用/冲击模型、公司行动处理和双重账本。阶段五不可变release是目标权重的唯一来源；原始价格负责成交和交易规则，后复权总收益用于独立核验。全部结果写入新的不可变backtest release，阶段六结束后先通过检查点B，才允许进入验证期。

**Tech Stack:** Python 3.12+、Polars、NumPy、SciPy、PyYAML、Matplotlib、pytest、ruff。

## Global Constraints

- 只运行2005-01-01至2016-12-31研究期；2017–2021验证期和2022–2025最终测试期继续封存。
- 只消费阶段五 `CURRENT.json` 指向的冻结release及其中 `size_stratified_buffered` 目标权重。
- 不修改候选因子、因子方向、复合权重、股票池、组合规模、规模分层和排名缓冲规则。
- 信号在月末t日收盘后形成，最早在下一真实市场交易日执行。
- 交易日来自实际市场日历，禁止自然日加1。
- 执行价格、股数、费用和现金使用不复权价格尺度；后复权价格不得直接乘原始股数计算市值。
- 公司行动处理未通过数据门禁前，不得宣称整数股现金账本或正式NAV正确。
- 当日总成交额不得用于当日开盘订单的事前容量判断；容量和冲击只使用t-1及以前的历史数据。
- Data只读；不覆盖阶段三MVP、阶段四或阶段五产物。
- 阶段六没有正收益也可通过；泄漏、错误成交、账务不平或隐瞒限制才是失败。
- 未经用户要求，不提交、不推送、不创建PR。

## 2. 数据可行性硬门禁

现有规范日面板含原始/后复权OHLC、前收盘、成交量额、ST和涨停标记，但没有明确的停牌字段、跌停字段和公司行动流水。阶段六开始编码前必须先完成以下审计。

### 2.1 成交状态字段

- 核验 `is_limit_up` 的原始字段含义：盘中触及、收盘涨停还是一字涨停；
- 研究期正式开盘成交规则不直接依赖含义未核验的 `is_limit_up`；
- 开盘买入阻断优先根据原始前收盘、适用涨跌幅和原始开盘价重算；
- 开盘卖出阻断同理重算跌停价，不使用未来收盘、高低价判断开盘订单；
- 停牌代理冻结为：市场交易日存在但证券无有效原始开盘价，或经证据证明的明确停牌状态；
- `volume/amount`只使用t-1及以前窗口计算ADV，不用当日收盘后数据决定开盘是否成交；
- ST历史口径未核验时，必须报告其对5%价格限制判断的影响。

### 2.2 公司行动

严格现金与整数股账本至少需要：

- 除权除息日期；
- 每股现金分红；
- 送股、转增和拆并股比例；
- 配股、供股等会改变股数或现金的事件；
- 事件生效时间和证券代码映射。

优先顺序：

1. 使用可缓存、可追溯的公司行动明细，并与交易所/上市公司公告抽样核对；
2. 可评估AKShare免费接口，但必须保存原始响应、拉取日期、接口版本、重试和缺失报告；
3. 后复权因子变化只可作为核验或异常发现，不可静默替代现金分红与股数事件；
4. 若无法构建可信公司行动流水，阶段六正式现金账本必须阻断；可以保留“总收益影子回测”作为诊断，但不得称为正式A股回测。

## 3. 冻结执行设计

### 3.1 时间线

```text
t日收盘后：读取冻结目标权重
  -> 下一市场交易日开盘前：生成目标股数和订单
  -> 开盘：先卖后买，应用可交易性、T+1、股数和现金约束
  -> 未成交部分：进入pending订单
  -> 每日收盘：公司行动、持仓估值、现金与NAV对账
  -> 下一调仓信号到来：撤销旧目标遗留订单，按新目标重建
```

- 市场交易日由规范日面板日期集合形成；
- 证券当天缺行不等于市场休市；
- 第一个目标日期之前只用于准备历史ADV和公司行动状态，不计入绩效；
- 最后一个信号必须允许下一交易日执行，但绩效截止日固定为2016-12-31之前最后一个市场交易日。

### 3.2 订单生成

- 开盘前资产基数为现金加持仓按可得开盘/上一有效收盘估值；
- 目标金额为开盘前资产乘冻结目标权重；
- 使用预估执行价计算目标股数；
- 买入股数向下取整至100股整数倍；
- 卖出后余额原则上保持100股整数倍；清仓时允许一次性卖出全部零股余额；
- 同日先处理卖单，再按确定性顺序处理买单；
- 现金不足时不按未来成交结果反复优化，采用预注册的比例缩减加100股舍入；
- 排序始终使用 `side_priority`、目标缺口绝对值降序、`symbol`升序。

### 3.3 可交易性与价格

- 基准成交时点固定为下一交易日开盘；
- 无有效原始开盘价：订单阻断并进入pending；
- 开盘价达到涨停价：买单阻断；开盘价达到跌停价：卖单阻断；
- 非对应方向不因价格限制自动阻断；
- 价格限制按原始前收盘、适用比例和0.01元最小价格单位计算；
- 滑点和冲击后的成交价不得优于原始开盘价，也不得越过当日价格限制；
- 仅有日线数据，不能声称精确模拟排队、盘口深度或盘中部分成交。

### 3.4 T+1与未成交订单

- 每笔买入记录 `available_to_sell_date`；买入当日不可卖；
- 卖出数量不得超过当日可卖数量；
- pending订单保存原始信号、创建日、剩余股数、阻断原因和存续天数；
- 可交易后按剩余股数继续尝试，不根据当天收盘后的信息回改早盘订单；
- 新调仓信号到来时，先撤销旧目标对应pending订单，再根据新目标重新计算；
- 订单状态固定为 `created/pending/partially_filled/filled/cancelled/expired/rejected`；
- 每次状态变化写入事件表，不覆盖旧状态。

### 3.5 成交容量、滑点和冲击

由于缺少盘口，采用透明、保守、可做敏感性的日线模型：

- `adv20`只使用t-1及以前20个有效交易观测的原始成交额；
- 单日单股成交金额上限为 `max_participation * adv20`；
- 超出上限的订单只成交可容纳的100股整数部分，其余进入pending；
- 固定滑点和平方根冲击分开记录；
- 建议冻结基准：固定滑点5bp、参考参与率1%、参考冲击10bp、最大参与率10%、单笔冲击上限50bp；
- 上述数字是模型假设，不是交易所事实，必须写入配置并在阶段七做敏感性；
- 若实际执行价经冲击后越过涨跌停价，则按无法成交处理，不在限制价虚构成交。

### 3.6 费用模型

每笔成交分别计算并保存：

- `commission`：买卖双边，基准率和最低佣金按账户假设配置；
- `stamp_duty`：按成交日历史费率和买卖方向；
- `transfer_fee`：按市场和历史制度；
- `slippage_cost`：相对原始开盘价；
- `impact_cost`：相对含固定滑点价格；
- `total_cost`：以上项目之和。

建议佣金基准为3bp、单笔最低5元，但必须明确这是可解释的账户假设，不是假装覆盖所有历史券商账户。零成本、仅显性费用、完整成本三套结果必须基于同一成交约束公平比较。

### 3.7 公司行动与估值

- 公司行动先按事件生效时点更新现金和股数，再处理当日订单；
- 现金分红进入现金流水；送转股改变持仓股数和可卖股数；
- 配股不默认参与，除非配置和事件数据能明确资金需求；
- 原始收盘价用于实际持仓市值；
- 当日无有效价格的持仓使用上一有效原始收盘估值，并标记stale及陈旧天数；
- 后复权总收益建立独立影子净值，用于发现漏记公司行动，不与原始股数直接相乘；
- 原始账本与影子净值出现超过冻结阈值的无法解释偏差时，运行失败。

## 6. 预计目标

阶段六完成后应得到：

1. 一套经过证据核验的2005–2016A股交易规则和历史费用表；
2. 一套可追溯的公司行动流水及覆盖/缺失报告；
3. 从冻结目标权重到订单、订单事件、成交、现金、持仓和NAV的完整链路；

7. 零成本、显性费用和完整成本的公平比较；

- 不允许根据研究期正式回测结果重新选择因子或组合规则。
