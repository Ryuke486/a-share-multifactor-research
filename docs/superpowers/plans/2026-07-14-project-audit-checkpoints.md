# A股多因子项目分层审计与检查点计划

**目标：** 在不重复浪费工作量的前提下，对新增阶段做深度审计、对历史阶段做回归验证，并在高风险阶段开始前阻断数据泄漏、接口错位和账务错误。

**适用范围：** 阶段一至阶段七的项目级检查。本文件规定何时检查以及检查深度，不替代各阶段实施计划。

---

## 1. 总体检查原则

采用以下分层方式：

> 新增阶段深度审计 + 历史阶段自动回归 + 端到端接口与血缘检查。

- 已经完成过深度检查的阶段，不重复逐文件从头人工审计；
- 历史阶段仍必须运行关键不变量测试、全量测试和接口检查；
- 自上次检查后新增或实质修改的阶段，必须接受完整审计；
- 跨阶段接口、日期边界、数据血缘和哈希每次都要检查；
- 若历史模块在后续阶段被修改，则该模块自动重新进入深度审计范围；
- 检查失败时停止进入下一阶段，不得用报告说明代替修复；
- 不以策略收益高低判断检查是否通过。

---

## 2. 三个项目级检查点

### 检查点A：阶段五完成后、阶段六开始前

这是下一次正式检查。

**目的：** 确认单因子研究、因子合成和目标权重链路正确，避免将研究错误带入正式成交回测。

**检查深度：**

| 阶段 | 深度 | 核心内容 |
|---|---|---|
| 阶段一 | 回归检查 | 配置、日期封存、防泄漏规则 |
| 阶段二 | 接口检查 | schema、主键、manifest、哈希和阶段四输入血缘 |
| 阶段三 | 轻量回归 | MVP原有测试和兼容性，不重新评价策略表现 |
| 阶段四 | 深度审计 | 因子、标签、中性化、评价、分类和因子卡片 |
| 阶段五 | 深度审计 | 候选准入、合成权重、滚动IC、目标权重和换手 |

**通过后才能开始：** 阶段六正式A股回测。

### 检查点B：阶段六完成后、打开验证期前

这是全项目最重要的一次检查。

**目的：** 确认正式回测的成交、成本和账本可信，并冻结进入样本外验证的模型与参数。

**重点：**

- t日信号与t+1真实交易日成交严格分离；
- 停牌、涨停买入失败、跌停卖出失败处理正确；
- A股T+1、整手、佣金、最低佣金和印花税正确；
- 未成交订单没有被当作成交；
- 现金、持仓市值和总资产逐日对账；
- 目标权重、订单、成交、持仓和NAV血缘一致；
- 研究期内模型、参数、成本和组合规则正式冻结；
- 2017年及以后数据在冻结前仍未被读取。

**通过后才能开始：** 2017–2021验证期评价。

### 检查点C：最终测试期完成后、项目交付前

**目的：** 确认最终测试期只使用一次，结果没有触发事后调参，代码、报告和答辩材料相互一致。

**重点：**

- 最终测试期打开时间和配置冻结时间有记录；
- 打开测试期后未修改因子、参数、组合和成本规则；
- 测试期结果可以从冻结版本复现；
- 正面、负面和不显著结果均被报告；
- README、研究报告、图表、机器可读结果和答辩材料数字一致；
- GitHub不包含原始数据、未授权数据或可再生大文件。

**通过后才能称为：** 完整、可复现、可用于复试展示的项目。

## 3. 检查点A执行清单

### 3.1 阶段一：回归检查

- [ ] `ResearchConfig`仍是全项目日期和路径的唯一配置入口；
- [ ] 研究期、验证期和测试期没有重叠；
- [ ] 阶段四和阶段五只允许读取2005–2016正式研究区间；
- [ ] 2017–2021和2022–2025读取门禁仍有效；
- [ ] 非法日期范围会被配置校验和自动测试拒绝；
- [ ] Data、processed和artifacts的Git保护仍有效；
- [ ] 阶段一原有测试全部通过。

**无需重做：** 不重新设计研究问题和样本划分，除非后续代码已经改变这些规则。

### 3.2 阶段二：接口检查

- [ ] 规范化日面板schema与阶段四实际消费字段一致；
- [ ] `(date, symbol)`主键唯一；
- [ ] symbol仍为六位字符串；
- [ ] 不复权和后复权数据仍是一对一连接；
- [ ] 37/38列schema变化处理没有被破坏；
- [ ] yearly parquet、manifest和质量报告仍可读取；
- [ ] 阶段四输入文件哈希与阶段二manifest一致；
- [ ] 原始Data没有被修改、移动或纳入Git；
- [ ] 阶段二相关测试全部通过。

**无需重做：** 不重新扫描全部28GB原始数据，除非manifest、哈希或输入文件发生变化。

### 3.3 阶段三：轻量回归

- [ ] MVP命令和原有小闭环测试仍能运行；
- [ ] t日信号、t+1执行和20日未来收益的反例测试仍通过；
- [ ] 阶段五改动没有破坏阶段三公共接口；
- [ ] 阶段三仍明确标记为管道验证，不被引用为正式因子结论；
- [ ] 不因后续结果回头翻转60日动量方向；
- [ ] 不重新生成或重新解释2014–2015净值结果。

**无需重做：** 不再人工逐笔审计MVP交易，也不重新评价MVP投资表现。

### 3.4 阶段四：深度审计

### 数据与股票池

- [ ] 阶段四只读取2003–2016，其中2003–2004仅用于预热；
- [ ] 动态股票池逐日形成，没有使用未来退市信息；
- [ ] 有效交易观测、上市历史和流动性门槛实现符合冻结规则；
- [ ] 因子面板主键 `(date, symbol, factor_name)` 唯一；
- [ ] 质量问题、隔离记录和面板行数可以相互对账。

### 因子与标签

- [ ] 14个因子公式、窗口和方向与预注册表一致；
- [ ] 因子仅使用信号日及以前数据；
- [ ] 5、20、60日未来收益只进入评价模块；
- [ ] 未来收益按证券有效交易观测对齐，不按自然日简单shift；
- [ ] 合成反例可以识别前视和错位；
- [ ] 估值因子仍标记point-in-time未核验。

### 预处理与评价

- [ ] 去极值和标准化按同日截面执行；
- [ ] 市值中性化没有使用未来或全样本信息；
- [ ] 未核验历史行业前没有实施行业中性化；
- [ ] Rank IC、Newey-West、FDR、分组收益和子区间口径一致；
- [ ] candidate/watch/reject分类严格执行冻结门槛；
- [ ] 6个candidate、5个watch、3个reject与机器可读结果一致；
- [ ] 动量reject没有被事后翻转；
- [ ] 因子卡片数字全部来自机器可读产物。

### 3.5 阶段五：深度审计

### 候选准入与合成

- [ ] 只有阶段四candidate进入正式合成；
- [ ] watch、reject和log_market_cap没有被当作正式收益因子；
- [ ] `candidate_equal`、`family_equal`和`representative_equal`权重可手算复核；
- [ ] 主方案三因子族各占1/3，不因族内因子数量改变族权重；
- [ ] 缺失因子处理和权重重归一规则确定；
- [ ] 复合分数主键唯一、方向统一、同日标准化；
- [ ] 输入行顺序和并列情况不会改变结果。

### 滚动IC防泄漏

- [ ] 权重日只使用截至上期已经实现的历史IC；
- [ ] 当期IC和未来IC不能改变过去权重；
- [ ] 36个月窗口、24个月门槛、负值截断和50%收缩符合配置；
- [ ] 历史不足和全零权重退回等权；
- [ ] 每个月的因子权重都有可追溯历史区间。

### 目标权重

- [ ] `top100_equal`选择和权重可手算复核；
- [ ] 规模五分组没有使用未来市值；
- [ ] 主组合正常月份每组20只、合计100只；
- [ ] 前30名缓冲只读取上期目标持仓；
- [ ] 权重非负、总和为1、无隐含杠杆；
- [ ] symbol并列时使用升序稳定排序；
- [ ] 规模组不足、缺失分数和异常月份被记录。

### 组合诊断

- [ ] 单边目标换手公式统一；
- [ ] 持仓数、最大权重、HHI和有效持仓数正确；
- [ ] 规模、因子和因子族暴露可复核；
- [ ] 容量代理使用信号日及以前成交额；
- [ ] 目标组合诊断没有被描述为真实成交收益；
- [ ] 阶段五没有提前实现或引用阶段六正式NAV。

### 3.6 端到端接口与血缘检查

完整检查以下链路：

```text
ResearchConfig
  -> daily_panel
  -> universe + forward_returns
  -> factor_panel
  -> factor_classifications
  -> composite_scores
  -> target_weights
```

- [ ] 每个对象的生产模块和消费模块唯一明确；
- [ ] 每个跨阶段文件都有schema、主键、日期范围和哈希；
- [ ] 下游没有绕过正式接口重新读取原始CSV；
- [ ] 报告模块没有重新计算另一套收益或权重；
- [ ] 修改任一上游文件会触发血缘校验失败；
- [ ] 阶段四和阶段五产物使用独立目录，不覆盖历史产物；
- [ ] 临时运行失败不会产生半新半旧的正式结果。

### 3.7 工程质量检查

- [ ] 运行阶段四、阶段五相关测试；
- [ ] 运行完整 `pytest -q`；
- [ ] 运行 `ruff check src tests`；
- [ ] 检查新增文件职责单一，没有继续扩大超大管道文件；
- [ ] 检查配置参数没有散落在Notebook或源码常量中；
- [ ] 检查所有bug修复均有对应回归测试；
- [ ] 检查Git状态，确认未误收Data、processed或artifacts；
- [ ] 检查README、AGENTS、阶段计划与实际结果一致。

## 4. 检查结果分级

### 必须阻断

出现以下任一情况，不得进入下一阶段：

- 读取了尚未获准打开的验证期或测试期；
- 因子、滚动权重或目标组合使用未来信息；
- 主键重复、日期错位或权重不守恒；
- manifest、哈希或血缘无法对应；
- 报告数字无法从机器可读产物复现；
- 全量测试或ruff失败；
- 原始数据被修改或纳入Git。

### 修复后复查

- 个别异常月份没有记录原因；
- 文档、计划复选框与实际状态不一致；
- warning严重度或说明不完整；
- 文件职责过重但尚未造成计算错误；
- 图表标签或报告措辞可能夸大研究结论。

### 可记录为已知限制

- 因子或组合研究期表现不佳；
- 滚动IC没有优于静态等权；
- 价值point-in-time、历史行业和ST口径仍未核验；
- 阶段五尚未包含真实成交约束；
- 合理规则下出现较高换手或容量限制。

---

## 5. 检查点A通过标准

只有全部满足以下条件，才建议开始阶段六：

- [ ] 阶段一至三回归检查通过；
- [ ] 阶段四和阶段五深度审计通过；
- [ ] 端到端血缘与哈希检查通过；
- [ ] 全量测试和ruff通过；
- [ ] 2017年及以后数据仍未读取；
- [ ] 主复合分数和主目标组合规则已经冻结；
- [ ] 已知限制完整记录；
- [ ] 形成独立的中期审计报告；
- [ ] 用户明确批准进入阶段六。

检查点A的目标不是证明策略有效，而是证明：

> 阶段六接收到的复合分数和目标权重是无前视、可复现、可审计且接口稳定的。

---

## 6. 后续检查复用规则

- 检查点B不需要再次完整重审阶段四和阶段五，除非其代码、配置或产物被修改；
- 检查点B仍需运行阶段一至五全量回归和血缘检查，并对阶段六做深度审计；
- 检查点C不重新选择模型，重点检查冻结纪律、复现性和报告一致性；
- 每次检查都应保存检查日期、Git提交、配置哈希、输入manifest、测试结果和审计结论；
- 任何影响样本、因子方向、成本、组合规则或评价指标的修改，都会使相关阶段重新进入深度审计范围。
