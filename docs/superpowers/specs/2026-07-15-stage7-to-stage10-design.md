# 板块7–10拆分设计

## 1. 目标

将原“样本外、稳健性与交付”拆成四个可独立验收的板块，保证2022–2025最终测试期在研究设计完全冻结后只打开一次。

## 2. 板块边界

1. **板块7：验证期评价与候选方案冻结**  
   只打开2017–2021，完成数据延伸、因子外推、组合与真实交易回测。允许依据预注册规则在简单基线中选定最终方案，但不读取2022年及以后数据。
2. **板块8：封存前稳健性与最终协议**  
   在2005–2021内对已选主方案做成本、调仓频率、股票池、因子删除和市场分段分析。稳健性只用于描述依赖性，不用于事后挑选最佳参数。末尾封存最终测试协议。
3. **板块9：最终测试期一次性评价**  
   只在用户明确批准后打开2022–2025，按封存协议执行一次。结果无论好坏均不触发调参或换模型。
4. **板块10：检查点C与项目交付**  
   先审计最终测试的一次性、冻结身份、数字一致性和GitHub数据安全，再完成研究报告、README、复现命令、结果表和图表。暂不制作答辩材料。

## 3. 数据和状态流

```text
stage6 research release
  -> stage7 validation release
  -> stage8 robustness release + sealed_test_protocol
  -> stage9 one-shot test release
  -> checkpoint C
  -> stage10 project delivery release
```

每个板块使用独立 `processed/<stage>/CURRENT.json`、不可变release、manifest和lineage；下游只解析上游 `CURRENT.json`，不直接引用临时run路径。

## 4. 不可违反规则

- 板块7和8不得读取、统计或绘制2022–2025数据。
- 板块9之前必须封存代码提交、配置、因子、组合、成本、指标和报告模板哈希。
- 最终测试结果打开后不得返回修改研究设计。
- 若发现计算bug，必须停止并记录；不得将bug修复包装为调参。是否使测试期降级由新的研究协议另行决定。
- 板块10不生成答辩PPT、答辩讲稿或口试题库。

## 5. 审计节点

- 板块7和8之间使用板块内验收，不重做项目级深度审计。
- 板块8结束时进行“最终测试开启前门禁”，必须由用户明确批准。
- 下一次项目级审计是检查点C：板块9完成后、板块10交付前。
