# 板块8最终执行协议继任封印设计

## 1. 目标

修复现有板块8封印无法覆盖2022–2025交易费用与公司行动输入的缺陷，在不读取最终测试行情、信号、组合或业绩结果的前提下，发布一个可审计、不可变的板块8继任release，使板块9任务4能够在新的用户授权后安全执行。

本次修复不改变因子、候选组合、调仓规则、成本模型结构、预注册指标或样本划分，只补齐最终执行协议的时间覆盖和输入证据契约。

## 2. 不触碰的范围

- 不读取或统计2022-01-01至2025-12-31的行情、因子、目标权重、成交或业绩。
- 不读取2026年数据。
- 不根据未来结果调整费率、公司行动处理、组合或报告口径。
- 不原地修改已发布的板块8 release。
- 不引入付费数据源，不扩展到质量、盈利、成长因子或新模型。
- 不提交、推送或创建PR，除非用户另行明确授权。

## 3. 发布与血缘

现有权威release `58adad4_stage8_robustness` 保持字节不变。新的板块8 successor release必须：

1. 在lineage中引用旧release身份、旧manifest哈希和被替代理由；
2. 将旧release标记为“协议覆盖不足、不可用于板块9最终执行”，但不删除或改写旧文件；
3. 绑定新的费用配置、公司行动源契约、覆盖审计规则、代码树、报告模板及上游release哈希；
4. 生成新的 `sealed_test_protocol.json`、manifest、lineage与 `CURRENT.json`；
5. 要求新的用户批准和新的HMAC开启令牌，旧令牌不得复用。

## 4. 历史费用补齐

`configs/market_rules.yaml` 的研究回测覆盖继续保持2005–2021，另将正式执行规则完整覆盖至2025-12-31：

- 印花税：2008-09-19至2023-08-27为买方0、卖方0.001；2023-08-28至2025-12-31为买方0、卖方0.0005。
- 沪深A股过户费：2015-08-01至2022-04-28按成交金额0.00002双向收取；2022-04-29至2025-12-31按成交金额0.00001双向收取。
- 佣金、最低佣金、滑点、冲击成本和最大参与率维持现有冻结值。
- 不单独新增交易经手费或证管费；现有模型继续将其视为券商佣金口径的一部分，避免改变已冻结成本模型结构。

费用加载器必须拒绝日期缺口、重叠、非有限数值、负费率和超出覆盖期的交易日。合成测试必须覆盖两个制度切换日前后，并验证沪深两市场和买卖双边。

## 5. 公司行动与证券事件源契约

采用“免费结构化数据 + 官方公告证据”的混合方案：

- BaoStock仅作为现金分红、送股、转增等结构化候选事件来源；
- 巨潮资讯、上交所、深交所等法定披露页面或公告PDF作为支付日期、比例及异常事件的官方证据；
- 所有网络响应、缓存文件和公告PDF均记录URL、抓取时间、字节数和SHA-256；
- 解析结果保留来源行、标准化事件和冲突说明，不覆盖原始缓存；
- 数据源失败、schema变化、重复主键、同一事件字段冲突或关键字段缺失必须失败关闭。

板块8 successor只封存获取代码、允许域名、查询范围、字段schema、标准化规则、证据规则与manifest格式，不提前获取2022–2025实际事件。实际事件在新的板块9授权登记成功后获取，并在读取最终行情之后、启动撮合之前形成attempt级输入manifest；其哈希绑定到本次授权和最终release。

## 6. 新增公司行动元数据覆盖审计

在重封板块8前，使用已开放的2017–2021验证期做历史回放审计，不接触最终测试期。审计目标是证明数据源契约和标准化逻辑足以支持执行账本，而不是重新评价策略。

硬门槛如下：

1. 查询覆盖：预定证券集合与年份组合100%有成功查询记录，包括明确的零事件响应；
2. 主键完整性：标准化 `action_id` 唯一，证券代码、除权日、事件类型和比例/金额字段满足schema；
3. 来源完整性：每个非零事件均可追溯到结构化原始响应；所有人工覆盖均绑定官方公告URL与文件哈希；
4. 冲突关闭：未解释的重复、日期冲突、比例冲突、支付日期倒置和负值数量必须为0；
5. 账本一致性：在2017–2021验证release中，标准化事件与已发布执行输入逐事件对比，关键字段差异数量必须为0；
6. 官方抽样：每个事件类别和每个年份至少抽取一项；若某类别或年份无事件，则记录零事件事实。样本中的除权日、支付日、现金金额和送转比例差异必须为0；
7. 审计产物：输出机器可读summary、逐事件diff、查询coverage、官方证据index和全部文件哈希。

任一门槛失败时，不生成新seal，也不得降低门槛、忽略异常或转入最终测试。

## 7. 审计发现后的上游更正

首次真实覆盖审计在2017–2021 BaoStock候选事件中发现4条支付日早于除权日的记录。官方公告复核确认：`002227`、`002335`、`002358`为支付日错误，`000042`还包含一条错误除权日的重复记录。处理规则如下：

1. 不修改BaoStock原始缓存，也不原地修改既有板块7 release；
2. 新增逐条官方公告URL、结构化证据快照和SHA-256绑定；
3. 仅按 `symbol + source_ex_date` 精确应用4条更正，之后继续执行既有业务主键去重；
4. 板块7以不可变successor重新双run、发布并在lineage中绑定旧CURRENT、manifest与lineage哈希；
5. 覆盖审计必须对新的板块7successor达到日期倒置为0、业务主键重复为0、候选与发布输入差异为0，才能继续板块8successor。

因此发布顺序调整为：板块7官方证据更正successor → 2017–2021覆盖审计 → 板块8双run与successor。最终测试期边界不变。

## 8. 数据流与模块边界

新增模块保持单一职责：

- `execution/fee_protocol.py`：验证费用区间完整性和制度切换；不负责撮合。
- `final_test/action_source_contract.py`：定义允许来源、查询范围、schema和原始缓存manifest；不读取行情。
- `final_test/action_coverage_audit.py`：在2017–2021比较候选事件、官方证据和已发布验证输入；不发布seal。
- `robustness/successor_seal.py`：验证所有门槛并构造不可变继任血缘；不运行最终测试。
- 板块9 `backtest.py`：只消费授权绑定且manifest验证通过的事件输入；不自行抓取或猜测公司行动。

数据流：费用与事件契约冻结 → 2017–2021覆盖审计 → 板块8双run复验 → successor release与新seal → 用户新授权 → 2022–2025事件获取及attempt manifest → 最终回测预检 → 阶段六执行器。

## 9. 失败处理与恢复

- 网络或数据源失败只留下失败尝试记录，不发布部分缓存为权威输入。
- 下载、manifest和release发布使用临时文件、文件fsync、原子替换及父目录fsync。
- 发布中断后依据状态机恢复；不得覆盖已存在的不可变release。
- successor seal生成前再次验证Git树、上游CURRENT、manifest、lineage、费用证据和覆盖审计哈希。
- 板块9任务4在任何缺失、冲突、未授权或哈希漂移时返回 `execution_started=false`、`publishable=false`。

## 10. 测试与验收

实施严格遵循RED → GREEN → REFACTOR：

- 费用测试：覆盖2022-04-28/29和2023-08-27/28边界、日期缺口、重叠及市场双边。
- 源契约测试：拒绝非允许域名、越界年份、schema漂移、路径逃逸和未哈希缓存。
- 覆盖审计测试：查询缺口、零事件响应、重复事件、字段冲突、支付日异常、官方抽样不足均必须失败。
- 继任发布测试：旧release保持不变，新lineage完整、旧令牌失效、CURRENT只能指向完整successor。
- 板块9回测测试：事件manifest必须绑定新seal和attempt，缺失时不得读取或启动撮合。
- 回归验证：相关测试、完整pytest、ruff以及两次2017–2021板块8运行；两次核心产物哈希必须一致。

完成标准是新板块8 successor release通过全部门禁并保持2022–2025行情与结果未读。此后板块9仍须取得新的用户开启批准，才能继续任务4。
